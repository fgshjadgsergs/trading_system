- [ ] REST /fapi/v1/openInterest каждые 5–10 с

- [ ] Запись: сырые сообщения append-only → parquet батчами, ротация по часам, партиции exchange/symbol/date
- [ ] Ежедневный автоотчёт качества: аптайм, гэпы, гистограмма задержек ts_recv − ts_event

### 1.2 История с data.binance.vision (параллельно, для бэктеста)

Соответствие «live-поток ↔ архив» — что заменяется, что нет:

| Live (websocket/REST) | На Vision | Вердикт |
|---|---|---|
| aggTrade | aggTrades | ✅ полная замена |
| kline любых ТФ | klines 1s…1mo + mark/index/premium | ✅ |
| bookTicker | bookTicker (весь поток лучших цен) | ✅ |
| openInterest 5–10 с | metrics (шаг 5 мин) | ⚠️ в 30–60 раз грубее |
| ратио L/S и taker | metrics (5 мин) | ✅ совпадает с live |
| forceOrder | liquidationSnapshot | ⚠️ собран из того же урезанного потока — тоже выборка |
| funding | fundingRate | ✅ |
| **depth@100ms (полный L2)** | ❌ только bookDepth — минутные срезы глубины на отступах от цены | ❌ полного стакана в архиве нет |

**Следствие:** карта ликвидаций, профиль объёма, CVD, сигналы S1–S3 — бэктестятся на Vision сразу за годы истории. Карта стакана и спуфинг-детектор — только на собственных записях из 1.1 (или платный Tardis, если понадобится глубина в прошлое).

- [ ] Скрипт массовой загрузки daily/monthly zip + проверка чексумм
- [ ] Нормализация архива в общую схему; единый ридер, которому всё равно, live-запись это или Vision
- [ ] Сверка пересечения: свои записи vs Vision за общие дни (trades и klines сходятся в допуске)
- [ ] Каталог датасетов: какие дни есть, какого качества

**Гейт 1:** 7 дней непрерывной собственной записи без немаркированных гэпов + скачан минимум год истории по трём символам.

### M4. Ядро — карта ликвидаций
- Функции: liq_price(entry, L, side, mmr) — сначала плоский MMR, потом таблица брекетов; allocate(ΔOI, w, доли сторон); update(H); consume(H, путь цены) — снятие пройденных зон; decay(H, Δt); бакет цены как доля ATR, не фиксированный тик. ### M6. Спуфинг-детектор (только на собственных записях L2)
Binance отдаёт L2 (уровни цен), не L3 (отдельные заявки) — поэтому детекция эвристическая, по жизни уровней.
- Функции: журнал событий уровня (появился / вырос / съеден сделками / снят без сделок — сопоставление изменений книги с лентой сделок); время жизни крупных уровней; cancel-to-fill ratio по стороне; флаг «мерцание» (крупный уровень ставится и снимается ≥ k раз за окно); детект айсберга (мгновенный refill после исполнения по той же цене); итог — stability score уровня 0..1, взвешивающий вклад «стены» в карту стакана
- Тесты: синтетические сценарии (честная стена / мерцающий спуф / айсберг) → верная разметка; реплей записанного дня с ручной разметкой 20–30 эпизодов, считаем precision/recall
- Виз: heatmap стакана с окраской по stability score; (seaborn) распределения времени жизни уровней: исполненные vs снятые
- [ ] код  [ ] тесты  [ ] виз

## Этап 3 — калибровка и валидация (самое сложное; не спешим)

### 3.1 Event studies — до всякой стратегии
- [ ] P(разворот в пределах k·ATR) после касания пула топ-децили vs базовая частота
- [ ] «Магнит»: P(дойти до пула на расстоянии d за время T)
- [ ] Поведение цены в LVN
- [ ] Значимость бутстрепом с поправкой на пересекающиеся события; все графики — seaborn с доверительными интервалами
- [ ] Если эффекта нет — стоп, возврат к модели карты. Это дешёвый выход, а не провал

### 3.2 Веса плеч: статика → динамика (заготовка будущей ML-модели)
- [ ] Ступень 1 — статика: глобальные w на трейн-окне. Метрика — capture rate: доля реальных ликвидаций (forceOrder + liquidationSnapshot) в топ-дециле ячеек по теплу
- [ ] Наивный бейзлайн (круглые числа + свежие экстремумы) обязан быть побит — иначе карта не работает
- [ ] Ступень 2 — скользящая: еженедельная пере-калибровка w на трейлинг-окне, walk-forward
- [ ] Ступень 3 — контекстная: w(context) из мульти-ТФ фич M3 (z-объёмы 1м…1д, импульсные бары, скорость ΔOI, funding, вола, сессия). Модель: softmax-регрессия или бустинг, предсказывающие распределение плеч либо напрямую интенсивность ликвидаций по бакетам
- [ ] Гипотезы проверяем, не постулируем: «открытые на импульсном объёме позиции сидят с большим плечом», «медленный набор на низком объёме — плечо ниже». Каждая — отдельный тест на данных
- [ ] Сравнение трёх ступеней только по OOS capture rate; усложнение без прироста откатываем

### 3.3 Walk-forward стратегии
- [ ] Калибровка на скользящем окне, тест строго out-of-sample, эмбарго-зазор между train и test
- [ ] Прогон по режимам (тренд/пила, высокая/низкая вола) и по трём символам
- [ ] Минимум параметров; каждый новый оправдывается приростом OOS, не in-sample

**Gate A:** карта бьёт наивный бейзлайн по capture rate.
**Gate B:** event-эффект статистически значим и переживает оценку издержек.
**Gate C:** положительный OOS-результат после комиссий и проскальзывания при вменяемой просадке.
