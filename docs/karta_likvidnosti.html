Модель · спецификация

Карта ликвидности

Оценка того, сколько долларов чужих позиций будет принудительно закрыто на каждом уровне цены. Не индикатор — счёт денег.

Так карта выглядит на графике: тёмный коридор вдоль цены — уровни, которые цена уже сняла; яркие полосы выше и ниже — доллары, которые ещё стоят.

  • 840 тестов зелёные
  • 1e-12 точность баланса массы
  • 1.000 совпадение карты между ТФ
  • Gate A не пройден — нет живых ликвидаций

§1

Что это такое одной фразой

Карта ликвидности — это оценка сколько долларов чужих позиций будет принудительно закрыто на каждом уровне цены. Не «уровень поддержки», не индикатор: это счёт денег. Если на $63.2 стоит $2 млн лонговых ликвидаций, значит при доходе цены до $63.2 биржа вынужденно продаст примерно на эту сумму.

Технически — словарь «ценовая корзина → тепло в USD», который обновляется на каждом баре: что-то добавляется (открылись новые позиции), что-то снимается (цена дошла и всё ликвидировала), что-то тускнеет со временем (позиции закрылись сами).

Ключевое слово — тепло (heat). Это доллары, а не абстрактные баллы.

§3

Ценовая сетка

Цена непрерывна, а карта хранит конечное число ячеек. Ось цены режется на корзины одинаковой ширины.

i = floor(P / S) номер корзины для цены P lo(i) = i · S нижняя граница (входит) hi(i) = (i+1) · S верхняя граница (НЕ входит) центр = (i + 0.5) · S
P
цена в USDT
S
ширина корзины в USDT
i
целый номер корзины — может быть отрицательным для дешёвых монет

Границы полуоткрытые: lo ≤ P < hi. Цена ровно на границе принадлежит верхней корзине, и только ей — иначе одна цена оказалась бы в двух корзинах сразу.

S = 0.1 · ATR привязка к волатильности инструмента S = P · bps / 10 000 привязка к цене (25 bps = 0.25 % цены)
Ширину нельзя брать из ATR того таймфрейма, на который смотришь. ATR минутного бара примерно в 40 раз меньше часового, и минутная карта вырождается в тысячи волосяных уровней. Сетка — свойство инструмента.
§4

Откуда берётся новое тепло

Сколько денег вошло

ΔOI = OI(конец бара) − OI(начало бара) в USD

ΔOI > 0 — открылись новые позиции, и они где-то будут ликвидированы. ΔOI < 0 — позиции закрылись (см. §7.2).

Как разделить между лонгами и шортами

LS = 0.4 · global_ls + 0.3 · top_ls + 0.3 · taker_ls LS = clip(LS, 0.1, 0.9) в лонги уходит ΔOI · LS в шорты уходит ΔOI · (1 − LS)
LS
доля притока, ушедшая в лонги
global_ls
доля лонгов среди всех счетов биржи
top_ls
доля лонгов среди крупных счетов, по позициям
taker_ls
доля агрессивных покупок в потоке сделок

Коэффициенты 0.4 / 0.3 / 0.3 — стартовые, они калибруются. Обрезание в [0.1, 0.9] не даёт одной стороне исчезнуть из-за одного кривого замера. Доли берутся строго назад по времени: бар видит только те замеры, что опубликованы до его закрытия — иначе карта подглядывает в будущее.

Как разделить по плечам

Никто не знает, кто с каким плечом зашёл. Приток делится по сетке плеч с весами.

сетка плеч L ∈ {3, 5, 10, 20, 25, 30, 40, 50, 60, 75, 100, 125} веса w = (w₁ … w₁₂), wₗ ≥ 0, Σ wₗ = 1 amount = ΔOI · (доля стороны) · wₗ деньги одного куска
L
плечо
wₗ
доля притока, зашедшая с плечом L
amount
доллары этого куска — они и станут теплом
Веса w — главный калибруемый объект модели. Их подбирают так, чтобы карта лучше всего совпадала с реальными ликвидациями (§12).
§5

Формула цены ликвидации

Ядро модели: она превращает «$100k зашли на плече 25x по цене $3.40» в «эти $100k сгорят на цене $3.27».

Базовая формула — Binance USDT-M, изолированная маржа

лонг: P_liq = ( E · (1 − 1/L) − cum/q ) / (1 − MMR) шорт: P_liq = ( E · (1 + 1/L) + cum/q ) / (1 + MMR)
P_liq
цена ликвидации — то, что ищем — USDT
E
цена входа в позицию, берём закрытие бара — USDT
L
плечо — раз
q
размер позиции — монеты
MMR
ставка поддерживающей маржи — доля, 0.005 = 0.5 %
cum
вычет поддерживающей маржи для тира — USD

Смысл E · (1 − 1/L): на плече L вы вносите 1/L от стоимости позиции; когда цена упала на эту долю, ваши деньги кончились. Деление на (1 − MMR) — потому что биржа закрывает не в ноль, а когда осталось MMR от нотионала. cum — поправка биржи, чтобы ставка не прыгала скачком на границе тиров.

Для лонга результат обрезается снизу нулём: позиция на плече 1x не ликвидируется вовсе, карта для неё ничего не размещает — такие деньги идут отдельной строкой dropped.

Формула совпадает с калькулятором биржи (WB + cum ∓ q·E) / (q·(MMR ∓ 1)) с точностью 1e-12 на всех тестовых случаях.

Тиры маржи

MMR не постоянна: чем больше позиция, тем выше ставка.

Нотионал до, USDMMRcum, USD

20 000 0005.0 %266 300
………

Это справочная таблица BTC-типа; в бою она тянется по каждому символу с биржи.

Тонкость: биржа берёт тир по нотионалу на цене ликвидации, а не на цене входа. Поэтому формула решается самосогласованно — перебираем тиры и берём тот, у которого

предыдущий_кап < P_liq · q ≤ кап_тира

Без этого тепло уезжает не туда: для 6 BTC на 2x разница между «тир по входу» и «тир по цене ликвидации» — сотни долларов на уровне.

Ограничение на размер счёта

ΔOI за бар — это деньги многих счетов, а тир выбирается по размеру одного. Если подставить весь агрегат, крупный приток попадает в тир с MMR ≥ 1/L — то есть в позицию, которая была бы ликвидирована в момент открытия. Биржа такую просто не откроет.

лонг: q_max = ( cap · (1 − mmr) + cum ) / ( E · (1 − 1/L) ) шорт: q_max = ( cap · (1 + mmr) − cum ) / ( E · (1 + 1/L) ) q = min(q, q_max)
cap
верхняя граница нотионала последнего тира, допускающего плечо L
mmr, cum
параметры этого тира
q_max
самый большой одиночный счёт, ещё жизнеспособный на этом плече

Тир допускает плечо, если L ≤ max_leverage тира — или, если биржа не дала капа, по консервативному эквиваленту mmr < 1/L.

Замер: доля кусков, попадавших на неправильную сторону от цены, упала с 16.9 % до 0 %.

Опция: типовой счёт по желанию

Вместо агрегата можно объявить, что типичный счёт имеет размер typical_account_usd, и выбирать тир по нему. Тогда цена ликвидации не зависит от того, сколько денег пришло за бар — что честнее физически: тир есть свойство счёта, а не потока.

§6

Куда именно кладётся тепло

Просто — по умолчанию

heat[ сторона ][ index(P_liq) ] += amount

С размытием по желанию

В реальности позиции с одним плечом входили не по одной цене, а по разбросу цен. Поэтому сумму можно размазать гауссовым ядром вокруг P_liq.

d = |P − P_liq| / P · 10 000 расстояние до уровня, bps σ_price = (σ₀ + σ₁ · d) · P / 10 000 ширина ядра, USDT σ_b = σ_price / S ширина ядра, в корзинах вес ячейки на смещении k ∝ exp( −0.5 · (k / σ_b)² )
σ₀
базовая ширина размытия, bps от цены
σ₁
насколько ядро расширяется с удалением уровня от цены — bps на bp
k
смещение ячейки от центральной, в корзинах

Ядро обрезается на ±3σ и не шире 41 корзины. Ячейки на неправильной стороне (лонговое тепло на уровне цены или выше, шортовое — на уровне или ниже) выбрасываются, остальные веса перенормируются. Масса сохраняется точно: ячейка с наибольшим весом забирает остаток от последовательного деления.

§7

Что снимает тепло

Механизмов три, и они принципиально разные: один локальный, два глобальных. Путать их — главный источник недоумения при взгляде на график.

7.1 Цена дошла — уровень сработал

За бар цена прошла отрезок [low, high]. Всё тепло на этом отрезке реализовалось: лонги ликвидированы по дороге вниз, шорты — по дороге вверх. Корзина снимается тогда и только тогда, когда

hi(i) > low И lo(i) ≤ high

Строгое > слева — потому что корзина, кончающаяся ровно на low, ценой не задета. Опционально края снимаются частично, пропорционально пройденной доле:

frac = ( min(hi(i), high) − max(lo(i), low) ) / ( hi(i) − lo(i) ) снимается h · frac

7.2 Позиции закрылись сами

Отрицательный прирост OI — добровольные закрытия. Такое тепло снимается со всей карты пропорционально:

factor = min( |ΔOI| · c / H , 1 ) каждая корзина: h ← h · (1 − factor)
H
суммарное тепло карты сейчас, USD
c
доля закрытий, которая реально несла тепло — close_out_fraction
factor
какая доля массы карты списывается
Зачем нужен c. Не всякая закрытая позиция стояла у ликвидации — многие закрылись далеко от неё или уже были съедены ценой. При c = 1 на закрытия уходит 68–76 % всей массы карты, и уровни не доживают до второго дня. При c = 0.5 медианная жизнь уровня выросла с 27 до 56 часов.

7.3 Время

Старые позиции постепенно перестают быть правдой: их закрыли, перевернули, перенесли. Каждый шаг всё тепло умножается на коэффициент:

keep = 0.5 ^ ( Δt / T½ ) h ← h · keep
Δt
сколько времени прошло, секунды
T½
период полураспада: за это время тепло уменьшается вдвое
keep
доля, которая осталась
Это глобальный механизм. На дневном баре с T½ = 24 ч один бар — ровно один полураспад, то есть минус 50 % у каждого уровня за свечу, ходила к нему цена или нет. Отсюда ощущение «затухают сразу все».

7.4 Смесь полураспадов по желанию

Одна экспонента означает, что шанс позиции исчезнуть в следующий час не зависит от того, сколько она уже прожила. У рынка это не так: импульсная толпа на 100x живёт часы, крупная позиция на 3x — недели. Поэтому тепло можно разложить на K слоёв со своими полураспадами.

S(t) = Σ wₖ · 2^( −t / Tₖ ) доля тепла, дожившая до возраста t приток делится: ΔOI⁺ · wₖ в слой k снятие ценой: одинаково для всех слоёв — геометрия общая закрытия: одна и та же ДОЛЯ массы с каждого слоя
wₖ
доля притока, попадающая в слой k — Σwₖ = 1
Tₖ
полураспад слоя k
S(t)
функция выживания: сколько осталось от исходной массы к возрасту t

Свойство смеси: эффективный полураспад растёт с возрастом тепла. Молодое гаснет быстро, дожившее живёт долго. Замер на демо-ряде: смесь 0.75·4ч + 0.25·14д даёт контраст картинки 0.603 при памяти 0.135, тогда как одна экспонента с той же памятью — контраст всего 0.504. Одной экспонентой обе величины сразу не получить.

Каждый слой — обычная карта со своей арифметикой, поэтому все проверки (баланс массы, точность снятия) работают послойно.

§9

Проверка на честность: баланс массы

Каждый доллар всегда находится в одном из пяти мест:

Σ heat = contributed − consumed − decayed − removed
contributed
всего положено тепла за всё время
consumed
снято проходом цены
decayed
ушло на затухание
removed
списано закрытиями при ΔOI < 0
dropped
приток без цены ликвидации, лонги на 1x — вне тождества

Тождество проверяется в тестах с точностью 1e-12 после сотен тысяч операций — накопители используют компенсированное суммирование Неймайера, иначе за 1e5 шагов уплывает последняя значащая цифра.

Если тождество нарушено — карта где-то потеряла или выдумала деньги. Оно ловит целый класс ошибок автоматически, без ручной проверки.
§10

Таймфреймы: одна карта, разные окна показа

Карта строится один раз на самом мелком доступном разрешении. Старший таймфрейм — это только выбор моментов показа: берётся кадр базовой карты на закрытие каждого бара показа.

Почему не пересобирать карту из баров каждого таймфрейма: на минутках это 60 мелких снятий и размещений внутри часа, на часовике — одно снятие всего диапазона и одно размещение на закрытии. Получаются разные карты.

ТФ показапересборка на каждом ТФодна карта, ТФ = окно показа
5m0.9391.000
15m0.8261.000
1h0.6781.000
4h0.5781.000

В таблице — косинус между итоговой картой и эталонной минутной на одной и той же истории. Затухание тут ни при чём: без затухания вовсе пересборка даёт 0.465.

Следствие: T½ не подгоняется под таймфрейм. Экспонента безпамятна, и время жизни позиции не зависит от того, какой график открыт у трейдера. T½ — свойство инструмента; на что его умножать, на стенные часы или на часы торговой активности, — отдельный калибруемый выбор.
§11

Как читать картинку

  • Тёмный коридор вдоль цены — там прошла цена, снятие очистило уровни.
  • Яркие полосы выше и ниже — стоящие пулы ликвидаций; чем ярче, тем больше долларов.
  • Полосы справа от последней свечи — проекция текущего состояния карты вперёд: «что ещё висит». Это отрисовка, а не прогноз.
  • Подписи вида $63.7K — сколько долларов стоит на этом уровне.
  • Цвет — логарифм тепла, нормированный по квантилям 0.55…0.995 ненулевых ячеек. Полный диапазон на плотной сетке вытягивает каждый слабый пул в яркую половину, и панель превращается в сплошную заливку.
§12

Как проверяется, что карта не врёт

Проверка идёт по реальному потоку ликвидаций forceOrder, который в саму карту не входит.

capture доля долларов реальных ликвидаций, попавшая в топ-дециль тепла hot_area_share какую долю площади карта вообще подсвечивает lift capture / hot_area_share

Смысл lift: карта, которая красит половину экрана, поймает много ликвидаций просто по площади. lift делит попадание на площадь и показывает, есть ли точность помимо ширины мазка.

Сравнение идёт с наивной базой: круглые уровни цены плюс недавние экстремумы свингов. Карта обязана обыгрывать эту базу на данных, которых не видела, с задержкой минимум в один бар — иначе она просто пересказывает уже случившееся.

  • формула ликвидации совпадает с калькулятором биржи до 1e-12, включая тиры и cum;
  • геометрия снятия проверена точной арифметикой на тысячах случайных случаев;
  • затухание совпадает с точной рекурсией: 2000 последовательных полураспадов расходятся на единицы ulp;
  • баланс массы держится с точностью 1e-12 после сотен тысяч операций;
  • быстрый векторный построитель для калибровки совпадает с основной картой с машинной точностью — 2.7e-16;
  • карта не зависит от таймфрейма показа: совпадение 1.000 по построению;
  • судья проверки прошёл канареечный тест — на данных без сигнала не даёт ложного прохода.

Не сделано

  • Gate A не пройден — нет живой записи forceOrder. Без неё нельзя ни откалибровать веса, ни доказать, что карта что-то предсказывает. Единственный блокер;
  • запись потоков с текущего IP не работает: биржа отдаёт только depth. Нужен VPS;
  • значения T½, c, σ, typical_account_usd — априорные догадки, не измерения;
  • быстрый построитель пока не умеет смесь полураспадов — нужно до её калибровки;
  • суб-баровое распределение притока OI: сейчас весь приток бара кладётся по цене закрытия.
Коротко: механика собрана и доказана, предсказательная сила — нет. Карта считает ровно то, что заявлено, без потерь и подглядываний в будущее. Полезна ли она для торговли — покажет калибровка на живых ликвидациях.
