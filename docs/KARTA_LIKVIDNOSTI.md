# Карта ликвидности: как она устроена

Документ описывает модель целиком: что подаётся на вход, какие формулы считаются,
что означает каждая буква в этих формулах, и что из этого проверено, а что нет.

---

## 1. Что это такое одной фразой

Карта ликвидности — это оценка **сколько долларов чужих позиций будет принудительно
закрыто на каждом уровне цены**. Не «уровень поддержки», не индикатор: это счёт денег.
Если на $63.2 стоит $2 млн лонговых ликвидаций, значит при доходе цены до $63.2 биржа
вынужденно продаст примерно на эту сумму.

Карта — это словарь «ценовая корзина → тепло в USD», который обновляется на каждом баре:
что-то добавляется (открылись новые позиции), что-то снимается (цена дошла и всё
ликвидировала), что-то тускнеет со временем (позиции закрылись сами).

Ключевое слово — **тепло** (heat). Это доллары, а не абстрактные баллы.

---

## 2. Что подаётся на вход

| Данные | Откуда | Зачем |
|---|---|---|
| Свечи OHLC | klines с биржи | цена входа новых позиций и путь, который цена прошла |
| Открытый интерес (OI) | `/fapi/v1/openInterest`, опрос раз в 7 с | прирост OI = сколько денег вошло в рынок |
| Доли сторон | `globalLongShortAccountRatio`, `topLongShortPositionRatio`, `takerlongshortRatio` | как разделить приток между лонгами и шортами |
| Таблица маржинальных тиров | `/fapi/v1/leverageBracket` | точная ставка поддерживающей маржи для формулы ликвидации |
| ATR | считается из свечей | масштаб ценовой корзины |
| Реальные ликвидации | поток `forceOrder` | **только для проверки**, в саму карту не входят |

Последняя строка важна: карта строится **без** знания реальных ликвидаций. Реальные
ликвидации нужны, чтобы проверить, угадала карта или нет.

---

## 3. Ценовая сетка (корзины)

Цена — непрерывная величина, а карта хранит конечное число ячеек. Ось цены режется на
корзины одинаковой ширины `S`.

```
i      = floor(P / S)          номер корзины для цены P
lo(i)  = i · S                 нижняя граница корзины (входит)
hi(i)  = (i+1) · S             верхняя граница (НЕ входит)
центр  = (i + 0.5) · S
```

| Буква | Что это |
|---|---|
| `P` | цена в USDT |
| `S` | ширина корзины в USDT |
| `i` | целый номер корзины (может быть отрицательным для очень дешёвых монет) |

Границы **полуоткрытые**: `lo ≤ P < hi`. Цена, попавшая ровно на границу, принадлежит
верхней корзине, и только ей — иначе одна цена оказалась бы в двух корзинах сразу.

Ширина корзины задаётся одним из двух способов:

```
S = 0.1 · ATR                     привязка к волатильности инструмента
S = P · bps / 10 000              привязка к цене (25 bps = 0.25 % цены)
```

**Важно:** ширину нельзя брать из ATR того таймфрейма, на который смотришь. ATR минутного
бара примерно в 40 раз меньше часового, и минутная карта вырождается в тысячи волосяных
уровней. Сетка — свойство инструмента, поэтому либо ATR фиксированного базового
таймфрейма, либо доля цены в bps.

---

## 4. Откуда берётся новое тепло

### 4.1 Сколько денег вошло

За бар прирост открытого интереса:

```
ΔOI = OI(конец бара) − OI(начало бара)      в USD
```

Если `ΔOI > 0` — открылись новые позиции, и они где-то будут ликвидированы.
Если `ΔOI < 0` — позиции закрылись (см. §7).

### 4.2 Как разделить между лонгами и шортами

```
LS = 0.4 · global_ls + 0.3 · top_ls + 0.3 · taker_ls
LS = clip(LS, 0.1, 0.9)
```

| Буква | Что это |
|---|---|
| `LS` | доля притока, которая ушла в лонги (long share) |
| `global_ls` | доля лонгов среди всех счетов биржи |
| `top_ls` | доля лонгов среди крупных счетов (по позициям) |
| `taker_ls` | доля агрессивных покупок в потоке сделок |

Коэффициенты 0.4/0.3/0.3 — стартовые, они калибруются. `clip(0.1, 0.9)` не даёт одной
стороне исчезнуть полностью из-за одного кривого замера.

Доли берутся **строго назад по времени**: бар видит только те замеры, которые были
опубликованы до его закрытия. Иначе карта подглядывает в будущее.

Тогда:

```
в лонги уходит   ΔOI · LS
в шорты уходит   ΔOI · (1 − LS)
```

### 4.3 Как разделить по плечам

Никто не знает, кто с каким плечом зашёл. Поэтому приток делится по сетке плеч с весами:

```
сетка плеч   L ∈ {3, 5, 10, 20, 25, 30, 40, 50, 60, 75, 100, 125}
веса         w = (w₁, …, w₁₂),  все wₗ ≥ 0,  Σ wₗ = 1
```

Сумма, которая уходит в один «кусок» (одна сторона × одно плечо):

```
amount = ΔOI · (доля стороны) · wₗ
```

| Буква | Что это |
|---|---|
| `L` | плечо |
| `wₗ` | доля притока, зашедшая с плечом `L` |
| `amount` | доллары этого куска, они и станут теплом |

Веса `w` — **главный калибруемый объект модели**. Их подбирают так, чтобы карта лучше
всего совпадала с реальными ликвидациями (§12).

## 5. Формула цены ликвидации

Это ядро всей модели: она превращает «$100k зашли на плече 25x по цене $3.40» в «эти
$100k сгорят на цене $3.27».

### 5.1 Базовая формула (Binance USDT-M, изолированная маржа)

```
лонг:   P_liq = ( E · (1 − 1/L) − cum/q ) / (1 − MMR)
шорт:   P_liq = ( E · (1 + 1/L) + cum/q ) / (1 + MMR)
```

| Буква | Что это | Единица |
|---|---|---|
| `P_liq` | цена ликвидации — то, что мы ищем | USDT |
| `E` | цена входа в позицию (берём закрытие бара) | USDT |
| `L` | плечо | раз |
| `q` | размер позиции | монеты |
| `MMR` | ставка поддерживающей маржи (maintenance margin rate) | доля, напр. 0.005 = 0.5 % |
| `cum` | вычет поддерживающей маржи для тира (maintenance amount) | USD |

Смысл `E · (1 − 1/L)`: на плече `L` вы вносите `1/L` от стоимости позиции. Когда цена
упала на эту долю, ваши деньги кончились. Деление на `(1 − MMR)` — потому что биржа
закрывает не в ноль, а когда осталось `MMR` от нотионала. `cum` — техническая поправка
биржи, чтобы ставка не прыгала скачком на границе тиров.

Проверка формулы: она совпадает с калькулятором биржи
`(WB + cum ∓ q·E) / (q·(MMR ∓ 1))` до 1e-12 на всех тестовых случаях.

Для лонга результат обрезается снизу нулём: позиция на плече 1x не ликвидируется вовсе,
для неё карта ничего не размещает (такие деньги учитываются отдельной строкой `dropped`).

### 5.2 Тиры маржи

`MMR` не постоянна: чем больше позиция, тем выше ставка.

| Нотионал до, USD | MMR | cum, USD |
|---|---|---|
| 50 000 | 0.4 % | 0 |
| 250 000 | 0.5 % | 50 |
| 1 000 000 | 1.0 % | 1 300 |
| 10 000 000 | 2.5 % | 16 300 |
| 20 000 000 | 5.0 % | 266 300 |
| … | … | … |

(это справочная таблица BTC-типа; в бою тянется по каждому символу с биржи)

Тонкость: биржа берёт тир по нотионалу **на цене ликвидации**, а не на цене входа.
Поэтому формула решается самосогласованно — перебираем тиры и берём тот, у которого

```
предыдущий_кап < P_liq · q ≤ кап_тира
```

Без этого тепло уезжает не туда: для 6 BTC на 2x разница между «тир по входу» и «тир по
цене ликвидации» — сотни долларов на уровне.

### 5.3 Ограничение на размер счёта

`ΔOI` за бар — это деньги **многих** счетов, а тир выбирается по размеру **одного**.
Если подставить весь агрегат, крупный приток попадает в тир с `MMR ≥ 1/L`, то есть в
позицию, которая была бы ликвидирована в момент открытия — биржа такую просто не откроет.

Поэтому размер зажимается сверху максимальным счётом, который биржа допускает на этом плече:

```
лонг:   q_max = ( cap · (1 − mmr) + cum ) / ( E · (1 − 1/L) )
шорт:   q_max = ( cap · (1 + mmr) − cum ) / ( E · (1 + 1/L) )
q = min(q, q_max)
```

| Буква | Что это |
|---|---|
| `cap` | верхняя граница нотионала последнего тира, допускающего плечо `L` |
| `mmr`, `cum` | параметры этого тира |
| `q_max` | самый большой одиночный счёт, который на этом плече ещё жизнеспособен |

Тир допускает плечо, если `L ≤ max_leverage` тира (или, если биржа не дала капа,
консервативный эквивалент `mmr < 1/L`).

Эффект замера: доля кусков, попадавших на неправильную сторону от цены, упала с 16.9 % до 0 %.

### 5.4 Опция: типовой счёт

Вместо агрегата можно объявить, что типичный счёт имеет размер `typical_account_usd`, и
выбирать тир по нему. Тогда цена ликвидации не зависит от того, сколько денег пришло за
бар — что честнее физически (тир — свойство счёта, а не потока).

## 6. Куда именно кладётся тепло

### 6.1 Просто (по умолчанию)

Вся сумма куска кладётся в одну корзину:

```
heat[ сторона ][ index(P_liq) ] += amount
```

### 6.2 С размытием (опция)

В реальности позиции с одним плечом входили не по одной цене, а по разбросу цен. Поэтому
сумму можно размазать гауссовым ядром вокруг `P_liq`:

```
d       = |P − P_liq| / P · 10 000                 расстояние до уровня, bps
σ_price = (σ₀ + σ₁ · d) · P / 10 000                ширина ядра, USDT
σ_b     = σ_price / S                               ширина ядра, в корзинах
вес ячейки на смещении k:  ∝ exp( −0.5 · (k / σ_b)² )
```

| Буква | Что это |
|---|---|
| `σ₀` | базовая ширина размытия в bps от цены |
| `σ₁` | насколько ядро расширяется с удалением уровня от цены (bps на bp) |
| `k` | смещение ячейки от центральной, в корзинах |

Ядро обрезается на ±3σ (не шире 41 корзины). Ячейки, попавшие на неправильную сторону
(лонговое тепло на уровне цены или выше, шортовое — на уровне или ниже), выбрасываются,
остальные веса перенормируются. Масса сохраняется точно: ячейка с наибольшим весом
забирает остаток от последовательного деления.

## 7. Что снимает тепло

### 7.1 Цена дошла — уровень сработал (`consume`)

За бар цена прошла отрезок `[low, high]`. Всё тепло, которое лежит на этом отрезке,
реализовалось: лонги ликвидированы по дороге вниз, шорты — по дороге вверх.

Корзина снимается тогда и только тогда, когда

```
hi(i) > low   И   lo(i) ≤ high
```

Строгое `>` слева — потому что корзина, кончающаяся ровно на `low`, ценой не задета
(границы полуоткрытые). Опционально края снимаются частично, пропорционально пройденной доле:

```
frac = ( min(hi(i), high) − max(lo(i), low) ) / ( hi(i) − lo(i) )
снимается h · frac
```

**Это единственный локальный механизм: он трогает только то, через что реально прошла цена.**

### 7.2 Позиции закрылись сами (`ΔOI < 0`)

Отрицательный прирост OI означает добровольные закрытия. Такое тепло снимается со всей
карты пропорционально:

```
factor = min( |ΔOI| · c / H , 1 )
каждая корзина:  h ← h · (1 − factor)
```

| Буква | Что это |
|---|---|
| `H` | суммарное тепло карты сейчас, USD |
| `c` | доля закрытий, которая реально несла тепло (`close_out_fraction`) |
| `factor` | какая доля массы карты списывается |

Зачем `c`: не всякая закрытая позиция стояла у ликвидации — многие закрылись далеко от
неё или уже были съедены ценой. При `c = 1` (буквальное прочтение) на закрытия уходит
68–76 % всей массы карты, и уровни не доживают до второго дня. При `c = 0.5` медианная
жизнь уровня выросла с 27 до 56 часов. Значение калибруется.

### 7.3 Время (`decay`)

Старые позиции постепенно перестают быть правдой: их закрыли, перевернули, перенесли.
Каждый шаг всё тепло умножается на коэффициент:

```
keep = 0.5 ^ ( Δt / T½ )
h ← h · keep
```

| Буква | Что это |
|---|---|
| `Δt` | сколько времени прошло, секунды |
| `T½` | период полураспада: за это время тепло уменьшается вдвое |
| `keep` | доля, которая осталась |

**Это глобальный механизм: он бьёт по всем уровням одинаково, независимо от того, ходила
к ним цена или нет.** На дневном баре с `T½ = 24 ч` один бар — это ровно один полураспад,
то есть минус 50 % у каждого уровня за свечу. Отсюда ощущение «затухают сразу все».

### 7.4 Смесь полураспадов (опция вместо одного `T½`)

Одна экспонента означает, что шанс позиции исчезнуть в следующий час не зависит от того,
сколько она уже прожила. У рынка это не так: импульсная толпа на 100x живёт часы,
крупная позиция на 3x — недели. Поэтому тепло можно разложить на `K` слоёв со своими
полураспадами:

```
S(t) = Σ wₖ · 2^( −t / Tₖ )        доля тепла, дожившая до возраста t
приток делится:  ΔOI⁺ · wₖ в слой k
снятие ценой:    одинаково для всех слоёв (геометрия общая)
закрытия:        одна и та же ДОЛЯ массы с каждого слоя
```

| Буква | Что это |
|---|---|
| `wₖ` | доля притока, попадающая в слой `k`, Σwₖ = 1 |
| `Tₖ` | полураспад слоя `k` |
| `S(t)` | функция выживания: сколько осталось от исходной массы к возрасту `t` |

Свойство смеси: **эффективный полураспад растёт с возрастом тепла**. Молодое гаснет
быстро, дожившее живёт долго. Замер на демо-ряде: смесь `0.75·4ч + 0.25·14д` даёт
контраст картинки 0.603 при памяти 0.135, тогда как одна экспонента с той же памятью
даёт контраст всего 0.504. Одной экспонентой обе величины сразу не получить.

Каждый слой — это обычная карта со своей арифметикой, поэтому все проверки (инвариант
массы, точность снятия) работают послойно.

---

## 8. Что происходит на одном баре

Порядок жёстко зафиксирован:

```
1. consume(low, high)      цена прошла — снять всё, что она задела
2. allocate(ΔOI, close)    новые позиции — положить тепло на их уровни ликвидации
3. decay(Δt)               время прошло — приглушить всё остальное
```

Сначала снятие, потом размещение: новые позиции этого бара открылись по его цене
закрытия и не могли быть ликвидированы внутри него же.

---

## 9. Проверка на честность: баланс массы

Каждый доллар всегда находится в одном из пяти мест:

```
Σ heat  =  contributed − consumed − decayed − removed
```

| Счётчик | Что это |
|---|---|
| `contributed` | всего положено тепла за всё время |
| `consumed` | снято проходом цены |
| `decayed` | ушло на затухание |
| `removed` | списано закрытиями (`ΔOI < 0`) |
| `dropped` | приток, для которого нет цены ликвидации (лонги на 1x) — вне тождества |

Это тождество проверяется в тестах с точностью 1e-12 после сотен тысяч операций
(накопители — компенсированное суммирование Неймайера, иначе за 1e5 шагов уплывает
последняя значащая цифра).

Если тождество нарушено — карта где-то потеряла или выдумала деньги. Оно ловит целый
класс ошибок автоматически.

---

## 10. Таймфреймы: одна карта, разные окна показа

Карта **строится один раз на самом мелком доступном разрешении**. Старший таймфрейм — это
только выбор моментов показа: берётся кадр базовой карты на закрытие каждого бара показа.

Почему не пересобирать карту из баров каждого таймфрейма: на минутках это 60 мелких
снятий и размещений внутри часа, на часовике — одно снятие всего диапазона и одно
размещение на закрытии. Получаются **разные карты**. Замер (одна и та же история, разная
нарезка, косинус с эталонной минутной картой):

| ТФ показа | пересборка на каждом ТФ | одна карта, ТФ = окно показа |
|---|---|---|
| 5m | 0.939 | **1.000** |
| 15m | 0.826 | **1.000** |
| 1h | 0.678 | **1.000** |
| 4h | 0.578 | **1.000** |

Причём затухание тут ни при чём: без затухания вовсе пересборка даёт 0.465.

Отсюда важное следствие: **`T½` не подгоняется под таймфрейм**. Экспонента безпамятна,
и время жизни позиции не зависит от того, какой график открыт у трейдера. `T½` — свойство
инструмента; на что его умножать (стенные часы или часы торговой активности) — отдельный
калибруемый выбор.

## 11. Как читать картинку

- **Тёмный коридор вдоль цены** — там прошла цена, `consume` очистил уровни.
- **Яркие полосы выше и ниже** — стоящие пулы ликвидаций; чем ярче, тем больше долларов.
- **Полосы справа от последней свечи** — проекция текущего состояния карты вперёд:
  «что ещё висит». Это только отрисовка, модель ничего не предсказывает этим.
- **Подписи `$63.7K`** — сколько долларов стоит на этом уровне.
- Цвет — логарифм тепла, нормированный по квантилям 0.55…0.995 ненулевых ячеек.
  Полный диапазон на плотной сетке вытягивает каждый слабый пул в яркую половину, и
  панель превращается в сплошную заливку.

## 12. Как проверяется, что карта не врёт

Проверка идёт по реальному потоку ликвидаций `forceOrder`, который в саму карту не входит.

```
capture         доля долларов реальных ликвидаций, попавшая в топ-дециль тепла карты
hot_area_share  какую долю площади карта вообще подсвечивает
lift            capture / hot_area_share
```

Смысл `lift`: карта, которая красит половину экрана, поймает много ликвидаций просто по
площади. `lift` делит попадание на площадь и показывает, есть ли точность помимо ширины
мазка.

Сравнение идёт с наивной базой: круглые уровни цены плюс недавние экстремумы свингов.
Карта обязана обыгрывать эту базу **на данных, которых не видела**, с задержкой минимум
в один бар — иначе она просто пересказывает уже случившееся.

## 13. Все параметры одним списком

| Параметр | Что задаёт | Значение по умолчанию | Как выбирать |
|---|---|---|---|
| `S` (`bucket_atr_fraction` / bps) | ширина ценовой корзины | 0.1 · ATR | по инструменту, не по ТФ графика |
| `leverage_grid` | какие плечи учитываем | 3…125 | по факту доступных на бирже |
| `w` | доли притока по плечам | равные / затравка | **калибруется** |
| `LS` | доля лонгов в притоке | 0.5 или из ратио-потоков | из потоков, коэффициенты калибруются |
| `MMR`, `cum` | тиры маржи | таблица с биржи | тянуть с биржи, не хардкодить |
| `typical_account_usd` | размер типового счёта для выбора тира | выкл. | калибруется |
| `σ₀`, `σ₁` | размытие уровня | выкл. | калибруется |
| `T½` | полураспад тепла | 24 ч | **калибруется**, единый для всех ТФ |
| `wₖ`, `Tₖ` | смесь полураспадов | выкл. | калибруется |
| `c` (`close_out_fraction`) | доля закрытий, снимающая тепло | 1.0 | калибруется |
| `fractional_edge_consume` | частичное снятие краёв | выкл. | по вкусу, влияет мало |

Все опции устроены одинаково: **значение по умолчанию воспроизводит прежнее поведение
бит в бит**. Включение любой из них — сознательный шаг, который должен окупиться на
калибровке.

## 14. Что сделано и что нет

**Работает и проверено (840 тестов, из них 282 стрессовых):**

- формула ликвидации совпадает с калькулятором биржи до 1e-12, включая тиры и `cum`;
- геометрия снятия проверена точной арифметикой (Fraction) на тысячах случайных случаев;
- затухание совпадает с точной рекурсией; 2000 последовательных полураспадов расходятся
  на единицы ulp;
- баланс массы держится с точностью 1e-12 после сотен тысяч операций;
- быстрый векторный построитель для калибровки совпадает с основной картой с машинной
  точностью (расхождение 2.7e-16 относительных);
- карта не зависит от таймфрейма показа (косинус 1.000 по построению);
- судья Gate A проверен канареечным тестом: на данных без сигнала он не даёт ложного
  прохода.

**Не сделано:**

- **Gate A не пройден** — нет живой записи `forceOrder`. Без неё нельзя ни откалибровать
  веса, ни доказать, что карта вообще что-то предсказывает. Это единственный блокер.
- запись потоков с текущего IP не работает: биржа отдаёт только `depth`. Нужен VPS
  (инструкция — `docs/DEPLOY_VPS.md`).
- значения `T½`, `c`, `σ`, `typical_account_usd` сейчас — априорные догадки, не измерения;
- быстрый построитель пока не умеет смесь полураспадов (нужно до её калибровки);
- суб-баровое распределение притока OI (сейчас весь приток бара кладётся по цене закрытия).

Коротко: **механика собрана и доказана, предсказательная сила — нет.** Карта считает
ровно то, что заявлено, без потерь и подглядываний в будущее. Полезна ли она для торговли —
покажет калибровка на живых ликвидациях.

## 15. Как запустить

```bash
# карта на нескольких таймфреймах из одной модели
python scripts/map_multitf.py --synthetic --symbol SUIUSDT --price 3.42 \
    --timeframes 1m 15m 1h 4h --days 5 --bucket-bps 25

# то же на реальных данных из лейка
python scripts/map_multitf.py --lake data/vision_lake --symbol BTCUSDT \
    --timeframes 1h 4h 1d --days 180

# кто съедает уровни: цена, закрытия или затухание
python scripts/decay_vs_consume.py

# сравнение законов затухания
python scripts/decay_law_frontier.py

# согласованность между таймфреймами
python scripts/tf_consistency.py

# проверка карты против реальных ликвидаций (нужен forceOrder в лейке)
python scripts/stage3_report.py --lake data/vision_lake --symbol BTCUSDT --lag-bars 1
```
