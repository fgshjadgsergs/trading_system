# Запуск живой записи: пошагово

Единственное, что сейчас отделяет карту от проверки, — записанный поток реальных
ликвидаций. Ниже порядок действий на машине, где запись будет крутиться.

Ветка с кодом: `claude/md-file-implementation-testing-eb4pzk`.

---

## Шаг 0. Проба: видит ли эта машина потоки (5 минут)

Это главный вопрос. С предыдущей сети Binance отдавал только стакан, всё остальное
глушилось — подписка подтверждалась, а данные не шли. Проверяем ДО того, как что-то
настраивать.

**Linux / macOS**

```bash
git clone -b claude/md-file-implementation-testing-eb4pzk \
    https://github.com/fgshjadgsergs/trading_system.git
cd trading_system
python3.11 -m venv .venv && .venv/bin/pip install -e .
.venv/bin/python scripts/ws_probe.py --seconds 20
```

**Windows (PowerShell)**

```powershell
git clone -b claude/md-file-implementation-testing-eb4pzk `
    https://github.com/fgshjadgsergs/trading_system.git
cd trading_system
py -3.11 -m venv .venv
.venv\Scripts\pip install -e .
.venv\Scripts\python scripts\ws_probe.py --seconds 20
```

В последней строке `ИТОГ:` должны быть **ненулевые** `aggTrade`, `markPriceUpdate`,
`kline_1m`. `forceOrder` в пробе почти наверняка будет 0 — он редкий, это нормально.

| Что в `ИТОГ:` | Что это значит |
|---|---|
| есть aggTrade, markPriceUpdate, kline | машина годится, идём дальше |
| только depthUpdate | эта сеть тоже режет потоки — нужен VPN или VPS в другом регионе |
| соединение не встаёт вовсе | провайдер блокирует Binance целиком — тот же вывод |

Пришлите мне строку `ИТОГ:` — по ней сразу видно, идти дальше или менять сеть.

## Шаг 1. Запуск записи

```bash
.venv/bin/python scripts/record_live.py --lake data/live_lake \
    --symbols BTCUSDT ETHUSDT SOLUSDT SUIUSDT
```

Символы: два «тяжёлых» (BTC, ETH) и два подвижных альта. Альты дают больше ликвидаций
на единицу открытого интереса — а для калибровки важно именно число событий, а не
объём. Больше четырёх символов брать не стоит: растёт трафик и диск, а пользы мало.

**Машина не должна засыпать.** Сон посреди записи = дыра в данных, и Gate 1 её не
простит.

- Linux, чтобы не думать про это вообще:
  ```bash
  sudo cp deploy/trading-recorder.service /etc/systemd/system/
  # поправьте в юните User=, WorkingDirectory= и путь в ExecStart= под свою машину
  sudo systemctl daemon-reload && sudo systemctl enable --now trading-recorder
  journalctl -u trading-recorder -f
  ```
  Сервис сам стартует после перезагрузки и перезапускается при обрыве.
- Windows: отключите спящий режим в настройках питания и оставьте окно открытым
  (или заведите задачу в «Планировщике заданий» с триггером «при входе в систему»).
- macOS: `caffeinate -i .venv/bin/python scripts/record_live.py ...`

Раз в минуту в лог пишется `stream_counts`. Там должны появиться `DepthDiff`, `Trade`,
`MarkPrice`, `Kline`, `OpenInterest`, `RatioPoint`, и со временем — `Liquidation`.

Диск: примерно 0.5–1 ГБ в сутки на четыре символа.

## Шаг 2. Контроль качества — через час, потом раз в день

```bash
.venv/bin/python scripts/quality_report.py --lake data/live_lake --symbol BTCUSDT
```

Отчёт печатает аптайм по каждому потоку и список гэпов. Правило Gate 1: **7 суток
записи без немаркированных гэпов**. Помеченный гэп (рекордер знал, что связь рвалась) —
не страшно; страшна дыра, о которой никто не знает, потому что на ней модель молча
обучится на неправде.

Если увидите гэпы — пришлите отчёт, разберёмся по причине: обрыв связи, сон машины
или отвал конкретного потока.

## Шаг 3. Сколько писать

| Срок | Что это даёт |
|---|---|
| 1 день | видно, что все потоки живые и лейк растёт как надо |
| 2–3 дня | первый черновой прогон Gate A: направление ясно, доверия ещё нет |
| 7 дней | Gate 1 закрыт |
| 2–4 недели | нормальная калибровка весов по плечам и T½: ликвидации редки, и на коротком окне их просто не хватает на честное разделение обучения и проверки |

## Шаг 4. Первый прогон проверки

```bash
.venv/bin/python scripts/stage3_report.py --lake data/live_lake --skip-download \
    --symbol BTCUSDT --embargo-days 0.25 --test-frac 0.3
```

Вердикт появится в `reports/stage3-btcusdt/README.md`. Там же — capture, доля
подсвеченной площади и lift против наивной базы.

Что означает результат:

- **карта обыгрывает базу** — переходим к калибровке весов, T½, close-out и σ;
- **не обыгрывает** — это тоже результат: значит модель в нынешнем виде не работает,
  и крутить параметры дальше бессмысленно, надо менять её устройство.
